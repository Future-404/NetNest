# ADR 0001: 同进程保留四个 PWA 暖会话

- 状态：已采用
- 日期：2026-07-29

## 背景

NetNest 原先只组合一个 `PwaWebViewScreen`。切换应用会释放 WebView，导致页面、
表单、滚动位置和前端运行状态重新加载。用户需要接近手机多任务切换的体验，同时
仍要维持每个 PWA 创建时选择的共享或独立 WebView Profile 策略。

Android WebView 的 `onPause()` 不会可靠暂停 JavaScript，而 `pauseTimers()` 会影响
进程内全部 WebView，因此不能用它实现单页面冻结。NetNest 也不为网页后台播放注册
MediaSession 或前台服务。

## 决策

采用一个同进程 `PwaSessionManager`，最多保留四个实时 WebView：

- 一个可见且可交互的 `ACTIVE` 会话；
- 最多三个不可见但继续按网页原有方式运行的暖会话；
- 第五个会话进入时按 LRU 回收最久未使用的非当前会话；
- 前台非当前会话空闲十分钟后回收；
- NetNest 进入后台两分钟后回收全部非当前会话；
- 收到内存压力或渲染进程退出时立即将非当前会话转冷；
- 自动回收前仅在内存中保存 WebView 导航栈，不把 URL、表单或认证参数写入磁盘。

所有打开入口统一调用 `activate(pwaId, source)`。普通入口重建 MRU 手势序列；
连续侧边手势使用冻结的四项环形序列，避免切换过程中顺序跳变。

## 交互

当前 PWA 可独立隐藏切换侧边条。侧边条的位置是全局非敏感偏好；点击打开最近四项
抽屉，长按后上滑/下滑切换，抽屉内暖会话可向屏幕外侧滑动关闭并在五秒内撤销。
安全、权限、通知或下载请求处于前台时禁止切换；后台会话的请求保留并显示关注角标。

## 后果

优点：

- 四个最近页面可近乎即时切换；
- Profile、Cookie 和站点数据继续遵循每个 PWA 创建时选择的共享或独立策略；
- MRU、回收和关闭规则是纯 Kotlin 状态机，可单元测试；
- 删除 PWA 时先移除暖会话；独立数据空间进入 Profile 延迟删除流程，共享数据空间则保留全局网页数据以免影响其他 PWA。

代价与限制：

- 最多四个 WebView 会增加内存、CPU、网络和电量消耗；
- 隐藏网页的脚本、网络和音频可能继续运行，多网页音频可能混合；
- WebView 导航恢复不保证恢复 DOM、表单、媒体位置或内存态；
- Android 杀死应用进程后，暖会话全部丢失，但 PWA Profile 数据仍按原策略落盘；
- 方案不是 Android 多进程或真正的浏览器页面冻结模型。

## 被否决的替代方案

- 每次切换销毁并重载：资源最低，但交互状态损失不可接受。
- 对隐藏 WebView 调用 `pauseTimers()`：影响同进程全部 WebView，无法按 PWA 控制。
- 每个 PWA 独立 Android 进程：隔离更强，但内存、进程协调、通知路由和 Profile
  生命周期复杂度显著增加，当前版本不采用。
